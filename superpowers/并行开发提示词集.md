## 二、通用铁律（每个提示词都隐含，子代理必须遵守）

1. **CODE-ONLY**：只改码，禁 `pnpm`/`install`/`verify`/`typecheck`/`lint`，禁碰 `node_modules`。
2. **禁碰 `packages/contracts/**`**（已冻结；确需改动先写原因上报审核）。
3. 只改本模块 `packages/<包名>/**`，不 import 其他 stage 内部实现，边界= `@test-platform/contracts` 类型。
4. 守代码规范（GLOBALS §8）：命名 / 文件≤300行 / 函数≤50行 / 嵌套≤3层 / 无 `any` / 无魔法数 / 每目录 README。
5. 开工前先核对真实进度（GLOBALS §7），勿照本提示词数字，以实际代码为准。
6. 改完只汇报，不擅自 commit/merge。

## 四、使用建议

- **并行窗口分配**：6 个 stage 修复彼此独立，可 6 窗并行；infra 4 包 1 窗；engine-mcp 1 窗；app 前端与 Electron 壳有依赖（先前端 provider 接口，再 Electron IPC），建议串行或同窗。
- **门禁集中**：所有子代理只改码，返回后由主 agent 集中 `pnpm -r typecheck && pnpm -r lint && pnpm -r verify`（串行前台，防卡死）。
- **修复优先级**：先 stage-login（FAIL 阻断）→ 其余 stage → app。
