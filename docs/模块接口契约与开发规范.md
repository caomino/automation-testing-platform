# 模块接口契约与开发规范 v1.2

> **目标**：从 0 到 1 落地开发，不返工。每个模块可并行开发，接口冻结后修改不污染其他代码。
> **配套**：`自动化测试平台-主规格.md`（WHAT/WHY） + `可执行PRD.md`（HOW 一步步） + 本文档（契约+规范+校验）

---

## 一、模块分解与冻结接口

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **Contract-first** | 先定接口（zod schema），后写实现。接口一旦冻结，只允许加字段（向后兼容），改字段 = 新 MAJOR + 迁移脚本 |
| **单向数据流** | 数据从 stage A → stage B 单向流动，不允许反向依赖 |
| **无循环依赖** | CI 用 `madge` 检查，有循环 = CI 红 |
| **只通过 contracts 传值** | 模块间不直接 import 对方的内部实现，只 import `contracts` 包中的类型和 schema |
| **每模块独立可测** | 每个 package 有自己的 `*.verify.ts`，可独立跑通不依赖其他模块 |

### 1.2 模块清单与依赖关系

```
contracts (0 依赖，所有模块依赖它)
├── infra-logger (依赖 contracts)
├── infra-ai (依赖 contracts)
├── infra-cred (依赖 contracts)
├── engine-mcp (依赖 contracts, infra-logger)
├── stage-login (依赖 contracts, engine-mcp, infra-cred)
├── stage-explore (依赖 contracts, engine-mcp)
├── stage-feature (依赖 contracts)
├── stage-case (依赖 contracts, infra-ai)
├── stage-execute (依赖 contracts)
├── stage-defect (依赖 contracts)
└── app (依赖以上所有，仅编排不实现业务逻辑)
```

**并行开发策略**：
- P0 阶段：`contracts` 先行（所有人依赖它），然后 `infra-*` 和 `engine-mcp` 可并行
- P1 阶段：`stage-feature` 和 `stage-case` 可并行（都只依赖 `contracts`）
- P3-P5 阶段：`stage-login`、`stage-explore`、`stage-execute`、`stage-defect` 可并行
- `app` 最后开发（仅编排层）

### 1.4 接口冻结规则

| 变更类型 | 级别 | 要求 |
|---------|------|------|
| 加可选字段 | PATCH | 无需迁移，向后兼容 |
| 加必填字段 | MINOR | 需提供默认值或迁移脚本 |
| 删字段 | MAJOR | 必须迁移脚本 + deprecation 2 minor 周期 |
| 改字段类型 | MAJOR | 必须迁移脚本 + deprecation 2 minor 周期 |
| 改字段语义 | MAJOR | 必须迁移脚本 + 全量 verify |

## 二、代码规范（AI 维护性 + 无屎山）

### 2.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 变量/函数 | `camelCase` | `buildFeatureMergeMap`, `testCaseRows` |
| 类型/接口/类 | `PascalCase` | `FeatureRow`, `CaseSheet`, `LoginInput` |
| 常量 | `UPPER_SNAKE_CASE` | `DEFAULT_FEATURE_COLUMNS`, `CASE_COLUMN_WIDTHS` |
| 文件名 | `camelCase.ts` / `PascalCase.tsx` | `caseFieldMapping.ts`, `App.tsx` |
| 目录名 | `kebab-case` | `stage-feature/`, `infra-logger/` |
| 枚举值 | `PascalCase` 或 `UPPER_SNAKE` | `'no-login'`, `'credential'`, `'manual-takeover'` |
| zod schema | `PascalCase + Schema` 后缀 | `LoginInputSchema`, `CaseOutputSchema` |
| verify 测试 | `*.verify.ts` | `featureId.verify.ts`, `caseBinding.verify.ts` |
| 禁止 | 拼音命名、缩写不明 | ~~`gongnengdian`~~, ~~`tpl`~~ (用 `template`) |

**注释要求**：
- 文件头：`@file` + `@description` + `@contract`（如有）+ `@frozen`（如冻结）
- 公共函数：TSDoc（`/** ... */`），含 `@param` / `@returns` / `@example`
- 复杂逻辑：行内注释说明为什么这么写（not what）
- 魔法数：必须提取为常量并注释

## 三、校验机制（防返工）

### 3.1 三层校验体系

```
开发时校验（编译期）
├── TypeScript strict（类型错误 = 编译失败）
├── ESLint strict（0 error 0 warning = CI 通过）
└── zod schema 定义（接口形状校验）

运行时校验（执行期）
├── zod schema 校验（stage 输入/输出自动校验）
├── 运行时断言（关键不变量硬断言）
└── 数据隔离 verify（执行前后快照比对）

集成测试（验收期）
├── *.verify.ts 契约测试（每个 stage 的 I/O 契约）
├── round-trip 测试（导入→导出 diff = 空）
└── 端到端测试（完整链路跑通）
```

### 3.2 zod schema 校验（运行时）

```typescript
/**

import { z } from 'zod';

/** CaseInput schema（运行时校验） */

  featureTable: z.array(z.array(z.string()).min(9).max(9)),  // 九列
  scope: z.enum(['selected_modules', 'all']),
  selectedModuleIds: z.array(z.string()).optional(),
  metaConfig: z.object({
    systemName: z.string(),
    testPointId: z.string(),
    testPoint: z.string(),
    testers: z.string(),
    clientStaff: z.string(),
    developerStaff: z.string(),
    firstTestDate: z.string(),
    regressionDate: z.string(),
    conclusionRule: z.string(),

  }),
  aiConfig: z.object({
    configId: z.string(),
    enabled: z.boolean(),
  }).optional(),
});

/** CaseOutput schema（运行时校验） */
export const CaseOutputSchema = z.object({
  caseWorkbook: z.array(z.object({
    sheetName: z.string(),
    meta: z.object({ /* MetaHeader fields */ }),
    rows: z.array(z.object({ /* CaseRow fields */ })),
    screenshotRef: z.string().optional(),
  })),
  caseRows: z.array(z.array(z.object({ /* CaseRow fields */ }))),
  metaHeader: z.object({ /* MetaHeader fields */ }),
```

### 3.3 运行时断言（关键不变量）

```typescript
/**
 * @file stage-case/src/assertions.ts
 * @description 关键不变量硬断言 — 违反 = 立即抛错，不允许继续
 */

/** 断言：用例编号 = 所绑定功能点的测试点标识（base_NN） */
function assertCaseNoBinding(caseRow: CaseRow, featureRow: FeatureRow): void {
  const expectedCaseNo = featureRow[DEFAULT_FEATURE_COLUMNS.testPointId]; // base_NN
  assert(
    caseRow.caseNo === expectedCaseNo,
    `用例编号绑定失败: caseNo=${caseRow.caseNo} ≠ featureId=${expectedCaseNo}`,
  );
}

/** 断言：测试内容 = 功能点.测试点 */
function assertContentMapping(caseRow: CaseRow, featureRow: FeatureRow): void {
  const expectedContent = featureRow[DEFAULT_FEATURE_COLUMNS.testPoint];
  assert(
    caseRow.content === expectedContent,
    `测试内容映射失败: content=${caseRow.content} ≠ testPoint=${expectedContent}`,
  );
}

/** 断言：功能点表每行恰好 9 列 */
function assertFeatureRowLength(row: FeatureRow): void {
  assert(
    row.length === 9,
    `功能点行列数错误: expected=9, actual=${row.length}`,
  );
}

/** 断言：用例表每行恰好 8 列 */
function assertCaseRowLength(row: CaseRow): void {
  const visibleFields = ['caseNo', 'content', 'step', 'operation', 'expected',
                         'firstResult', 'regressionResult', 'conclusion'];
  visibleFields.forEach(field => {
    assert(row[field] !== undefined, `用例行缺字段: ${field}`);
  });
}

/** 断言：测试点标识 = 3 段 base（系统缩写_父目录缩写_子系统缩写） */
function assertTestPointIdFormat(testPointId: string): void {
  const parts = testPointId.split('_');
  assert(
    parts.length === 3,
    `测试点标识格式错误: expected=3段(base), actual=${parts.length}段, value=${testPointId}`,
  );
}

/** 断言：用例编号 = 4 段 base_NN */
function assertCaseNoFormat(caseNo: string): void {
  const parts = caseNo.split('_');
  assert(
    parts.length === 4,
    `用例编号格式错误: expected=4段(base_NN), actual=${parts.length}段, value=${caseNo}`,
  );
  const nn = parts[3];
  assert(
    /^\d{2}$/.test(nn),
    `用例编号后缀格式错误: expected=2位数字, actual=${nn}`,
  );
}

/** 断言：同一子系统内 NN 唯一递增 */
function assertSubsystemNNUnique(caseRows: CaseRow[], subsystemBase: string): void {
  const nns = caseRows
    .filter(r => r.caseNo.startsWith(subsystemBase))
    .map(r => r.caseNo.split('_')[3]);
  const unique = new Set(nns);
  assert(
    unique.size === nns.length,
    `子系统 ${subsystemBase} 内 NN 不唯一: ${nns.join(',')}`,
  );
}
```

## 四、并行开发对接方式

### 4.1 Contract-first 工作流

```
Step 1: 在 contracts 包中定义接口 + zod schema（所有人评审，合并后冻结）
Step 2: 各模块并行开发，仅依赖 contracts 中的类型和 schema
Step 3: 每模块先写 *.verify.ts（跑红），再写实现（跑绿）
Step 4: 模块间通过 run(input): Promise<Output> 通信，不直接 import 内部实现
Step 5: app 包编排各 stage，仅调用 run()，不实现业务逻辑
```

### 4.2 模块间通信规则

| 规则 | 说明 |
|------|------|
| 只调 run() | 模块间只通过 `run(input)` 调用，不 import 内部函数 |
| 只传 contracts 类型 | 输入输出只用 contracts 中定义的类型，不用模块内部类型 |
| zod 自动校验 | run() 内部第一行 = `validateInput(input)`，最后一行 = `validateOutput(output)` |
| 错误码统一 | 错误用 contracts 中定义的错误码常量，不抛自由文本 |
| 不共享状态 | 模块间不共享变量/缓存/单例，只通过 input/output 传值 |

## 七、scope 选择机制（用例生成 + 执行）

> **UX 规范（v1.4）**：选择面板默认隐藏，不常驻页面。用状态栏 `[📋 已选 N/M 模块] [⚙ 选择模块] [生成选中] [全部生成]` 呈现当前状态；点击「选择模块」弹出模态勾选，确认后状态栏计数刷新。执行页为系统→模块树形列表，逐行显示用例状态（✓ 已执行 / ⏳ 执行中 / 未执行），树形勾选即执行 scope。

### 7.1 用例生成 scope

```typescript
/** 用例生成范围 */
type CaseScope = 'selected_modules' | 'all';

/** 用例生成流程 */
async function generateCases(input: CaseInput): Promise<CaseOutput> {
  // 1. 按 scope 过滤功能点
  const filteredFeatures = input.scope === 'selected_modules'
    ? filterByModuleIds(input.featureTable, input.selectedModuleIds)
    : input.featureTable;

  // 2. 按 module 分组
  const grouped = groupByModule(filteredFeatures);

  // 3. 每组生成用例
  const caseSheets = await Promise.all(
    grouped.map(async ([moduleName, features]) => {
      const rows = await generateCaseRows(features, input.metaConfig, input.aiConfig);
      return { sheetName: moduleName, meta: input.metaConfig, rows };
    })
  );

  // 4. 质量门检查
  const qualityGateIssues = await runQualityGate(caseSheets);

  return { caseWorkbook: caseSheets, caseRows: caseSheets.map(s => s.rows), ... };
}
```

### 7.2 执行 scope

```typescript
/** 执行范围 */
type ExecuteScope = 'selected_modules' | 'all';

/** 执行流程 */
async function executeCases(input: ExecuteInput): Promise<ExecuteOutput> {
  // 1. 按 scope 过滤用例
  const filteredSheets = input.scope === 'selected_modules'
    ? input.caseWorkbook.filter(s => input.selectedModuleIds.includes(s.sheetName))
    : input.caseWorkbook;

  // 2. 执行前数据快照
  const snapshotBefore = await captureDataSnapshot();

  // 3. 浏览器×OS 矩阵执行
  const results = await Promise.all(
    input.browserOSMatrix.flatMap(env =>
      filteredSheets.flatMap(sheet => sheet.rows.map(row => executeCase(row, env)))
    )
  );

  // 4. 执行后数据快照 + 隔离验证
  const snapshotAfter = await captureDataSnapshot();
  const isolationVerified = verifyIsolation(snapshotBefore, snapshotAfter);

  return { executionReport: results, dataSnapshotBefore: snapshotBefore, dataSnapshotAfter: snapshotAfter, isolationVerified };
}
```

## 八、项目 CRUD 接口（v1.5 当前系统模型）

> **底层单系统原则**：所有系统底层都是单系统，**类型只决定登录方式与 URL 来源，不存在"登录路径"模型**。门户 = 可直接登录且可作为子系统登录入口；单系统 = 直接登录；子系统 = 经父门户浏览器会话捕获 URL 后进入，其余流程与单系统完全一致。
