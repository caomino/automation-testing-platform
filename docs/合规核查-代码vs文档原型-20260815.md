## ③ 「写了但偏离」明细（核心交付）

### ③-1 用例列宽常量与文档不符　⚠️ 待产品裁定
- **文档要求**（R-A-07）：用例八列列宽 = `[18,16,8,34,34,14,14,12]`。
- **代码实际**（`contracts/src/types/CaseRow.ts:45`）：
  `export const CASE_COLUMN_WIDTHS: number[] = [21.25, 17.62, 14.62, 31.75, 8.43, 8.43, 8.43, 8.43];`
- 代码注释称该值是「xlrd 对金标准 xls 实测」。两种可能：① 文档给的是近似/规范值，实测值更准；② 代码偏离了文档契约值。
- **建议**：由产品/测试负责人裁定哪一组为权威。若以文档为准，需改 `CASE_COLUMN_WIDTHS`；若以实测为准，需同步修订主规格 R-A-07 的数值，避免后续 review 误判。

### ③-2 测试点缩写无「真拼音」算法　⚠️ 潜在风险
- **文档要求**（R-A-01）：base = 系统缩写_父目录缩写_子系统缩写，**中文取拼音首字母大写**（如 QYYX_PZ_JCX）。
- **代码实际**（`abbreviation.ts:9-44`）：`toAbbrToken` 仅对 ASCII id 做「去前缀+大写」（如 `sys_qyyx`→`QYYX`），纯中文标识会走 `shortHash` 退化为 6 位十六进制（非拼音首字母）。
- 当前样例（节点 id 用拼音 ASCII 约定）表现与文档一致，但**输入纯中文时会产出非拼音哈希**，与字面要求不符。
- **建议**：在 `abbreviation.ts` 补一套「中文→拼音首字母」兜底，或明确约束「模块节点 id 必须为拼音/ASCII」，并将该约束写回文档。

### ③-3 缺陷环境字段大小写未归一化　⚠️ 轻微
- **文档/原型示例**（R-06）：`Win11·Chrome·QYYX_PZ_JCX_01/S2`（首字母大写）。
- **代码实际**（`stage-defect/src/logic.ts:33-39`）：`${env.os}·${env.browser}${ver}·${caseNo}${tail}`，模板与分隔符正确，但 `env.os/browser` 是自由字符串，无首字母大写映射；上游传入 `win11`/`chrome` 时输出即 `win11·chrome·…`。
- **建议**：在 `deriveEnvironment` 对 `os/browser` 做首字母大写或显式枚举映射。

## ④ 「依赖未打通」断点清单（代码在，但跑不通）

### ④-1 credential 登录完全不可用　⛔
- 链路：`stage-login/src/index.ts:250` 默认凭证工厂 = `createCredentialStore`；`infra-cred/src/index.ts:30-32` 该函数直接 `throw`；`index.ts:184` 构造 store 即抛，被 catch 成 `status:failed`、空 cookies。
- 影响：R-S-02 的 credential 模式在真实环境是死路；仅测试注入 fake store 能走通。
- **修复前置**：补齐 `infra-cred` 真实实现（凭证存储 + safeStorage）。

### ④-2 门户会话复用不可达　⛔
- 链路：engine-mcp 的 `McpEngine` 接口与 `PlaywrightEngine` 均无 `getSessionCookies/getSessionTokens`；`stage-login/src/index.ts:196-197` 用可选链 `?.()` 降级为 `[]`；`reuseSession`（`:277-279`）复制的是空凭据会话。
- 影响：R-01「共享门户会话复用」当前无法传递任何鉴权凭据，跨子系统自动登录失效。
- **修复前置**：在 `PlaywrightEngine` 实现 cookie/token 读取（或提供真实 `SessionCapableEngine`）。

### ④-3 用例执行是启发式占位　⚠️（非断点，但远未达标）
- `engine-mcp/src/playwright-engine.ts:163-176` `runCase` 仅按操作文本前缀 click 首个语义节点，无 fill、不逐步执行、多步用例只产单条结果。
- 影响：R-05「按步骤执行用例」目前只能跑通最浅路径；真实用例执行需补全步骤序列解释与逐步驱动。
