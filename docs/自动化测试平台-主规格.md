## 2. 五阶段总览与隔离原则

| 阶段 | 一句话 | 输出 |
|------|--------|------|
| ① 登录与跨域 | 三模式登录（免登录/账号密码/人工接管），人仅接管验证码/手机号 | `SessionHandle` |
| ② 探索 | MCP 遍历 + 模块树 CRUD + 人工补充 | `ModuleTree` |
| ③ 功能点审核 | 九列 + 合并 + 增删 + 整体确认 | `FeatureTable`(confirmed) |
| ④ 测试用例 | 八列 + meta 可编辑 + 选中模块/全部 + 分 sheet | `CaseTable` |
| ⑤ 执行 / 缺陷 | 独立两阶段 | `ExecutionReport` / `DefectTable` |

**隔离铁律**：每 stage 独立 package，`run(input): Promise<Output>`；数据流单向幂等；**I/O Boundary 冻结**（§5 各表），改 stage 内部不影响其他。

## 3. 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 桌面封装 | **Electron** | 自带 Chromium = 自动化浏览器同引擎；testmaster 先例；免 Rust |
| 探索/登录 | **Playwright MCP**（单例可见浏览器） | AI 驱动探索正合适；TestProject 已验证 |
| 执行 | **Playwright 直连** | 确定性强，免 LLM 每步，更快更稳 |
| 凭证 | **Electron `safeStorage`** | OS 密钥（DPAPI/Keychain/libsecret）+ 本地 enc |
| 日志 | 外部 `${LOG_DIR}` 或 OS 标准应用数据目录 | 项目内不污染 |
| AI 模型 | **独立配置页**（§14），多厂商 + 中转站 | 灵活切换，不写死 |
| 代码 | strict TS + ESLint(strict) + 每 stage `*.verify.ts` | §13 开发规范 |

## 15. 复杂逻辑生成机制（分层 · 手动开关 · 自动识别弹提示）

**5 层机制**：

| 层 | 机制 | 覆盖 |
|----|------|------|
| ① 关键字模板 | `templateScenarioEngine`(`D:\Test\src\domain\testCases\templateScenarioEngine.ts:72`) 按动作关键字产 3~7 条 + depth | ~70% 常规 CRUD + 常见流程 |
| ② AI 辅助（带证据门） | 低置信/模板未覆盖 → 调 AI：输入=页面 snapshot + 业务上下文 + 已收集证据 + 功能点元数据；输出=步骤+预期；**无截图/无业务理解→拒绝生成，标 needs_review** | 复杂流程/条件分支，只接受有证据的 |
| ③ 人类审查 | 在线编辑纠错 = 人工审核关；改/删后 `sanitizeCaseRowsAgainstFeatureRows`（`D:\Test\src\domain\testCases\caseRows.ts:157`）自动重对齐 | 全部，错的生成前改掉 |
| ④ 质量门 | `qualityGate.ts`（`D:\Test\src\domain\testCases\qualityGate.ts`）：泛化/缺证据/越权 = blocker | 全部，硬把关 |
| ⑤ 项目自定义规则 | 项目可注册业务规则模板（如"审批必须 3 节点"、"金额>1万需复审"），引擎注入对应场景 | 业务特定逻辑 |

**手动开关**：项目设置「AI 辅助生成」**默认 OFF**；用户显式开启才走 ②。

**自动识别弹提示**：生成时启发式检测复杂逻辑（模板未匹配 / 多步骤 / 条件分支 / 跨模块 / 自定义规则命中）→ 弹"检测到复杂逻辑，建议开启 AI 辅助生成，是否开启？"→ 用户确认后开启 ②。

**诚实边界**：AI 增而不替。真正新颖、无证据、纯靠猜的复杂逻辑，AI 不出（出就是骗）。AI 出的每一步附证据/置信度，人在看板一眼可判。

## 18. 系统模型与工作流（v1.5 更新 · 底层单系统原则 + 登录三模式 + 当前系统视图）

### 18.1 底层模型（根本原则）

> **所有系统底层都是单系统。类型之间的差异是「登录方式」，不是「登录路径」。**

每个系统都是独立实体：有自己的 URL、自己的完整流程（登录 → 探索 → 功能点 → 用例 → 执行 → 缺陷）。**每个系统都有自己的登录方式，三选一**，任何类型都可选：

| 登录方式 | 行为 | 凭证 |
|---------|------|------|
| **免登录** `no-login` | 直接访问 URL，无需登录 | 不需要 |
| **账号密码登录** `credential` | 自动填表登录，凭证存 safeStorage | 需要账号密码（必填） |
| **人工接管登录** `manual-takeover` | 打开浏览器，人在 UI 接管完成登录 | 需要账号密码（参考/失败重试） |

| 系统类型 | 登录方式 | URL 来源 | 附加 |
|---------|---------|---------|------|
| 门户 `portal` | 三选一（同上） | 手动输入地址 | 可作为其他子系统的登录入口（父门户） |
| 单系统 `standalone` | 三选一（同上） | 手动输入地址 | — |
| 子系统 `subsystem` | 三选一（同上） | **浏览器捕获**（选父门户 → 显示父门户路径 → 经门户会话打开捕获） | 父门户路径只读显示 |

> 不存在"登录跳父门户 → 回到本系统"的路径模型——经父门户打开只是子系统 **URL 的获取方式**。类型带来的差异只有两点：① 门户可作为父门户；② 子系统 URL 经浏览器捕获。登录方式配置三种类型完全一致。

**废除 v1.3 的"门户子系统模式 / 单系统模式 toggle"概念** —— 模型里不存在模式切换，只有"当前上下文在哪个系统"。

### 18.2 项目结构（一个项目 = 多系统）

```typescript
interface Project {
  id: ProjectId
  name: string
  type: 'portal' | 'standalone' | 'subsystem'
  systems: System[]   // 1..n
}
interface System {
  id: SystemId
  name: string
  type: 'portal' | 'standalone' | 'subsystem'
  url: string                        // 门户/单系统=手动输入；子系统=浏览器捕获
  parentPortalId?: SystemId          // subsystem 时必填，跨项目引用所有 portal 系统
  parentPortalPath?: { name: string; url: string }  // subsystem 时只读显示
  credentialMode: 'no-login' | 'credential' | 'manual-takeover'  // 三选一，所有类型一致
  credentials?: { username: string; passwordRef: string }  // mode ≠ no-login 时必填
  loginState: 'logged_out' | 'logged_in'
  progress: { explored: boolean; featured: boolean; cased: boolean; executed: boolean }
}
```

**新建项目表单**：项目名称 + 项目类型（单选：门户/单系统/子系统）+ 类型相关字段（门户/单系统 → URL 手动输入 + 登录方式三选一 + 账号密码（除免登录外）；子系统 → 父门户下拉（跨项目列所有 portal 系统）+ 父门户路径只读显示 + 子系统 URL 浏览器捕获 + 登录方式三选一 + 账号密码）+ [创建并启动浏览器登录]。

### 18.3 上下文与切换（v1.5：工作台改为当前系统视图）

- **Topbar 只读路径**：`📁 项目 › 🖥️ 系统(URL) › 📂 子系统(URL)`，URL 等宽小字内嵌 chip；topbar pill 显示当前系统登录状态（per-system）；**无任何切换交互**
- **工作台（屏①）**：以**当前系统**为单位呈现——登录状态 / 阶段进度 / 用例数 / 执行情况 / 快速操作 / 最近活动；**不显示项目级总览/全系统列表/阶段矩阵**
- **切换系统**：工作台头部 [🔀 切换系统 ▾] 下拉 或 屏⑨ 项目管理的系统列表；`setActiveSystem(systemId)` 全应用跟随（topbar + 工作台 + 各 stage 数据）
- **切换项目**：只在屏⑨（所有项目列表点击行）；工作台不再有"切换项目"按钮
- **探索前先登录**：工作台快速操作第一位为 [🔐 登录系统]；[🔍 进入探索] 检查登录状态，未登录则弹登录窗阻止
- **登录不设独立页面/侧栏入口**：登录只是弹窗（m-login），仅由工作台快速操作按钮或探索前置门触发
- **登录方式带入项目管理配置**：登录弹窗展示该系统在项目管理中配置的登录方式（免登录/账号密码/人工接管），**只读不可改**；账号自动回填（密码 safeStorage 解密填充），登录按此配置方式执行；如需更换登录方式须回项目管理修改
- **独立状态**：每个系统在各阶段有独立数据，切换不丢失状态

### 18.4 系统列表（屏⑨ 项目管理）

全系统列表从工作台移至屏⑨ 项目管理："当前项目系统列表"——每个系统一行：系统名 + 类型徽章 + URL + 登录方式（三选一之一）+ 父门户（subsystem 时显示）+ 阶段进度 + 进入按钮。点击行 = 切换当前系统 + 全应用跟随。

### 18.5 系统注册增强

注册时捕获完整信息：URL + 页面标题（从浏览器自动捕获）、会话状态（cookies/headers/tokens）、导航路径。子系统经父门户浏览器会话捕获 URL。

### 18.6 人工补录（v1.5：两段式）

**弹窗职责（极简）**：录制状态显示 + 录制路径表格 + [写入待入树列表] 按钮。弹窗**不直接插入树**。

**待入树列表（探索屏 body 永久卡片）**：列 = `#` / `录制路径` / `所在模块` / `置信` / `状态` / `操作`。每行右侧三按钮：
- **[入树(插入下方)]** —— 需先选中模块树某行；无选中时灰显
- **[修改]** —— 编辑所在模块或录制路径
- **[删除]** —— 从列表移除

列表顶部：[✓ 全部入树] [✗ 忽略]。批量入树同样需先选中模块树目标行。

### 18.7 复制到 Excel（v1.5 新增）

功能点审核屏 + 测试用例屏各加 [📋 复制到 Excel] 按钮：浏览器剪贴板写入 HTML（含 colspan 合并单元格）+ TSV（制表符分隔）双格式，粘贴到 Excel/WPS 保留格式与内容。

### 18.8 屏⑩ 知识库（v1.5 新增）

- **结构**：🌐 通用 + 每系统各一个文本框（无条目概念）
- **数据模型**：`KnowledgeBase { globalPrompt: string; systemPrompts: Record<SystemId, string> }`
- **AI 调用规则**：任何 AI 调用（功能点生成 / 用例生成 / AI 辅助执行）在系统 X 上下文中注入：系统 X 提示词（高优先）+ 通用提示词（低优先）；内容重复/冲突时**系统提示词优先级 > 通用提示词**
